# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A static **web app** ("MetaPrompt") that rewrites a user's raw idea into an expert-grade prompt for another LLM. `index.html` is the studio and `settings.html` the settings page. Everything runs in the browser: it calls either the Anthropic Messages API directly or OpenRouter, with automatic failover across a configured model list, using the user's own key.

The project used to be a Chrome MV3 extension (plus a macOS wrapper). Those files now sit in `.trash/extension-and-macos-2026-10-01/` (gitignored) and are not part of the app; do not reintroduce page rewriting, context menus, shortcuts or badges.

There is no build step and no dependency. `npm start` runs `web/server.mjs` (ES modules do not load from `file://`); any static host can serve the same files. There is no lint config.

Checks are offline and need no API key, network, or build — run them with `npm test`
(or individually: `npm run test:prompt|test:brain|test:runtime|test:efficiency|test:memory|test:placeholders|test:web`,
i.e. `node verify_prompt.js`, `node verify_brain.js`, `node verify_runtime.mjs`,
`node verify_efficiency.js`, `node verify_memory.mjs`, `node verify_placeholders.mjs`, `node verify_web.mjs`). There is no per-case
filter; each script is a single suite. Run them after any change to the prompt,
brain, config, API, efficiency, memory, placeholder, or web layers. The runtime suite prints
`TypeSafe classification failed: HTTP 500` / `offline` — those are its fail-open
mocks, not failures.

## Running

- `npm start` → http://127.0.0.1:5173/ (override with `PORT` / `HOST`). Reload the tab after edits; there is no watcher.
- Logs: the browser DevTools console of the studio tab (the engine runs in the page).

## Architecture

```
index.html
  web/shim.js (classic)   chrome.storage.local → localStorage ("metaprompt:" prefix), chrome.runtime ports/messages in-page
  engine.js   (module)    port "revise" + REVISE_PROMPT + REWARD_BRAIN
     ├─ efficiency.js      (outermost semantic cache + Psi compression)
     ├─ memory.js          (opt-in Mnemonist memory: recall related past revisions)
     ├─ config.js          (active provider + key + model)
     ├─ typesafe.js        (optional task classifier, fail-open)
     ├─ brain_helper.js    (runs SNN tick via brain_network.js)
     ├─ hda_agents.js      (five HDA phase agents)
     ├─ prompt.js          (detectTaskType, buildSystemPrompt, buildUserMessage)
     └─ api.js             (reviseWithFailover / reviseStreamWithFailover → Anthropic or OpenRouter, block KV)
  studio.js   (module)    UI: connects to the "revise" port, renders deltas, history
     └─ placeholders.js    (fill the [PLACEHOLDER]s of a finished prompt, no model call)
settings.html
  web/shim.js + settings.js   provider/key/model, OpenRouter model tools, TypeSafe, cache
```

Web-layer rules:

- `web/shim.js` must load as a classic script before any module. It implements only `chrome.storage.local` (get with null/string/array/defaults-object keys, callback and promise forms; Infinity/NaN encoded as `{__mpNumber}` because the SNN state stores them) and `chrome.runtime` (`connect` ports, `sendMessage` with async `sendResponse`, `openOptionsPage` → `settings.html`). The engine modules keep using `chrome.storage.local`, so do not hardcode `localStorage` elsewhere.
- The pages must keep every element id `studio.js`/`settings.js` look up; `verify_web.mjs` asserts this.
- Each page's CSP `connect-src` allows only Anthropic, OpenRouter and TypeSafe. Widening it sends user text to new hosts — change it deliberately, in both pages and in `web/server.mjs`.
- `web/server.mjs` binds 127.0.0.1 and serves only the root, `web/` and `icons/`, a fixed file-extension allowlist, no dotfiles, no traversal (`resolveRequest` is pure and tested).
- Design lives in `web/app.css` ("Chat Studio", one stylesheet for both pages): light chat layout — white canvas, `#f9f9f9` sidebar that becomes a drawer under 900px, black pill buttons for primary actions, violet `#6d4aff` only for selection and focus, Geist / Geist Mono, shadows only on floating layers (composer, dialogs). The studio is a sidebar (modes, recent history, key status) plus a composer; advanced settings (strategies, HDA mode, consensus, output language) sit in the composer's Options panel and length in the depth dialog — keep every control reachable when changing the layout. Views toggle with the `hidden` attribute; results render with `textContent`, never `innerHTML`. The previous black "constellation" design is in `.trash/pre-chatstudio-2026-10-01/`.

Key cross-file contracts:

- **Provider config** is split per-provider so switching doesn't wipe the other's key/model. `config.js` defines the `PROVIDERS` map (field names, defaults, suggestions). `getActiveConfig()` returns `{ provider, apiKey, model }`; `getFailoverConfig()` returns `{ provider, apiKey, apiKeys, models }` — both revision paths in `engine.js` use the latter. Two invariants live here: the list is capped at `MAX_BACKUP_MODELS + 1` entries, and backups stay **inside the active provider** unless the user ticks the `crossProviderFallback` option in Settings. Widening either one means the source text reaches models the user never chose, so change them deliberately. Everything reads these from `chrome.storage.local` (the shim) — do not hardcode storage keys elsewhere.
- **API layer** (`api.js`) exposes `reviseWithFailover({ provider, apiKey, apiKeys, models, system, userText, maxTokens })` and a streaming twin `reviseStreamWithFailover({ ..., onDelta })` (SSE; 30s idle timeout; fails over to the next model only if no text has streamed yet — after first delta, errors propagate instead of silently restarting). Both iterate the `models` array, stop early on 401/403, and (for OpenRouter) read/maintain `openrouterWorkingModels` in storage to seed future failover. The two providers have different request/response shapes — Anthropic uses `x-api-key` + separate `system` field + content blocks; OpenRouter uses Bearer + system-as-message + `choices[].message`. Both are handled in this one file.
- **Prompt building** (`prompt.js`) is the "Ana Beyin" methodology: `detectTaskType()` classifies the raw text score-based into coding/analysis/email/summary/translation/explain/planning/creative/general. It is bilingual: text and keywords are folded to plain ASCII via `foldDiacritics()`, so "ozetle" and "özetle" both match and `"İ".toLowerCase()`'s combining dot stops mattering. False positives are stripped before scoring — English "postal code"/"barcode" and Turkish "posta kodu"/"barkod"/"güvenlik kodu" — and "<qualifier> programı" is rewritten to a planning marker, because it is a schedule while the English "program" keyword would score it as coding. Ties break specific-to-general via `TASK_PRIORITY`, then `buildSystemPrompt(language, rawText, snnValues, mode?, vibeStrategy?, researchStrategy?, antihalluStrategy?, length?, taskTypeOverride?, hda?)` assembles the system message. The standard path is length-aware: `kisa` prunes the rubric/workflow/tools modules and the format few-shot example; it adds a protected Feynman rule — `explain` gets `FEYNMAN TEACHING` (12-year-old plain language, mechanism behind each term, everyday analogies, closing re-explain questions; `kisa` gets a one-sentence version; the keyword `feynman` routes to explain), every other task type except `translation` gets a deliverable-adapted `FEYNMAN CLARITY` line (`MODULES.feynman`), and vibecoding/research/antihallu get theirs from `FEYNMAN_MODE_RULES` via `insertBeforeMandate`; every variant ends with `FEYNMAN_DEFAULTS` so an audience/level stated in the RAW TEXT wins, and `PROTECTED_PATTERNS` keeps them through compression; it always appends fidelity rules (preserve verbatim details, no invented facts — use `[PLACEHOLDER]`s) and a prompt-injection guard for RAW TEXT. The output is intended to be a **prompt for another LLM**, not an answer to the user's question — keep that invariant when editing prompt templates.
- **Caveman module** (`prompt.js`: `MODULES.caveman`, `CAVEMAN_INPUT`, `CAVEMAN_ANSWER`, `cavemanRuleFor()`, `CAVEMAN_MODE_RULES`; adapted from the Apache-2.0 JuliusBrussee/caveman `caveman`, `caveman-compress` and native-core/lean-build skills — the rest of that skills folder is Caveman CLI/service tooling and does not apply here). Always on, one protected `CAVEMAN OUTPUT` line per prompt (`PROTECTED_PATTERNS`). Input side: the expert prompt itself is written dense (no filler/pleasantries/hedging, short imperative sentences; literals, `[PLACEHOLDER]`s, negations and every RAW TEXT detail verbatim; Turkish keeps suffixes). Output side: coding/analysis/planning/general and the vibecoding/research/antihallu modes tell the target model to answer terse, with caveman's auto-clarity exceptions (security, irreversible, ordered steps, ambiguity) and "clarity wins" over brevity; research/antihallu keep uncertainty markers as evidence. Precedence: explain keeps the Feynman teaching tone and email/creative/summary/translation deliverables keep normal sentences — only the prompt's instructions are compressed there. `kisa` gets a one-sentence variant. The RAW TEXT itself is never compressed.
- **Agent CLI mode** (`mode: "agentcli"`, `prompt.js`: `AGENT_CLI_REGISTRY`, `detectAgentTarget()`, `buildAgentCliSystemPrompt()`): writes a ready-to-paste prompt for an autonomous coding agent — Claude Code or OpenAI Codex CLI (storage key `agentTarget`: `auto`/`claudecode`/`codex`; auto picks Codex on "codex"/"AGENTS.md" mentions, else Claude Code). Output = at most one leading command from the target's catalog, then the four-part golden prompt (Scope & Role, Steps, Constraints, Verification). The catalogs are condensed from the user's `claude-code-prompt-system.md` / `codex-prompt-system.md` (2026-10-01, not checked against live CLI docs; Claude Code's review command is `/code-review`) and are a closed list — every CLI-version-dependent fact lives in `AGENT_CLI_REGISTRY` only. Invariants: catalog, safety and core rule lines (role, closed list, headless quoting, placeholders, no fences) carry the protected `AGENT CMD:` / `AGENT SAFETY:` / `AGENT RULE:` markers, because the default orta prompt exceeds the compression budget; skip-approval flags (`--yolo`, `--dangerously-*`) only when the RAW TEXT says isolated container/CI; exploration defaults to read-only/plan; destructive steps get an approval stop; unknown files/commands become `[PLACEHOLDER]`s; headless form (`claude -p` / `codex exec`) only on request. `agentTarget` is appended to the semantic-cache fingerprint only in this mode (older keys stay valid). The mode gets the coding Feynman and Caveman rules; the SNN runs as `coding`. `buildSystemPrompt` takes `agentTarget` as its last parameter.
- **Placeholder filler** (`placeholders.js`, studio only — never in the engine): after a prompt finishes (or opens from history) `extractPlaceholders()` finds its `[UPPERCASE]` slots and the studio shows a "Fill in the blanks" panel (`fillPanel`/`fillFields`/`fillCount`). Deterministic, no model call, because a filled value may only come from the user: what they type, the value they used last for the same slot name (`placeholderValues`, local, ≤ `MAX_REMEMBERED_NAMES` × `MAX_VALUES_PER_NAME`, written on Copy), or a verbatim span of their raw text matched to the slot type (`classifyPlaceholder()`: dir/path/command/url/email/branch/version/date/number, bilingual via `foldDiacritics`). Prefill only when unambiguous (remembered value, or exactly one text candidate); several become datalist suggestions; unknown and secret slots are never guessed, and secrets / values `redact.js` would mask are never remembered. Extraction skips code indexing (`items[IDX]`), markdown links, checkboxes, numbers, mixed-case brackets (deliberate: `[MeSH term]`) and line-start section labels (`[Scope & Role]:`). `fillPlaceholders()` substitutes in one callback pass (no `$&` expansion, no cascading). The unfilled result stays the source of truth — history stores it, `#output` shows the filled text, so Copy copies the filled prompt. "Clear all history" also clears `placeholderValues`.
- **HDA audit layer** (`prompt.js`: `HDA_PHASES`, `buildHdaDirective()`): the five-phase Cartesian-Hylomorphic Thinking Algorithm (epistemic filter, conceptual analysis, intentionality check, rational inference, hylomorphic synthesis). `buildSystemPrompt` inserts it in **every mode**, directly before the language mandate (which must stay the last line); the model runs it silently on the raw text and its own draft, so the output is still only the expert prompt. `kisa` gets an actions-only version. Storage key `hdaMode` (studio "HDA thinking algorithm" select): `agents` (default) runs the five **phase agents** in `hda_agents.js` as sequential `reviseWithFailover` calls before the revision — each gets the raw text (capped at `HDA_MAX_PHASE_CHARS`) plus the previous phase's full output; `kisa` runs only phases 2 and 4. Their report goes into the user message as an escaped `<hda_analysis>` block (`buildUserMessage({ hdaReport })`) and `buildSystemPrompt(..., hda = "agents")` adds rules to use it as data that never outranks the RAW TEXT. Any phase failure falls back to the inline audit (`hdaStatus: "inline-fallback"`) — keep that, the agents may slow a revision but must never block it. `inline` = directive only; `off` = none; legacy `hdaEnabled: false` still means off. Progress: studio port message `{type:"hda", index, total, name}`. When HDA is not off, the consensus judge adds two checks — premise promotion and equivocation.
- **TypeSafe classifier** (`typesafe.js`) is an optional, opt-in layer over the prompt brain's task detection. It asks TypeSafe one System One **Choice** question — which of the nine task types the raw text is — and `engine.js` passes the answer to `buildSystemPrompt(..., taskTypeOverride)`, which prefers it over `detectTaskType()`. It is deliberately **not** in `PROVIDERS`: it never serves a revision and must never enter the failover model list. It fails open at every step (no key, opt-in off, HTTP error, timeout, unknown task type, confidence below the user's threshold) by returning `null`, which both revision paths read as "use the keyword detector" — preserve that, a classifier outage must not break a revision. Only the first `MAX_CLASSIFY_CHARS` of the source text are sent, and the toggle defaults off for the same reason `crossProviderFallback` does: it ships user text to a third service. The wire format follows docs.typesafe.ai/api.md (checked 2026-09-22): `POST /v1/systemone`, model `jev-latest`, `questions` as an object keyed by id, answer at `answers.task_type.choice`. The original `/v1/ask` + questions-array shape returned 404, so the layer had been silently falling back to keywords. Everything version-dependent is confined to the constants, `buildClassifyRequest()` and `readChoiceAnswer()` in that one file.
- **SNN simulation** (`brain_network.js` + `brain_helper.js`): a biophysical Leaky-Integrate-and-Fire network with Tsodyks-Markram STP, STDP, and neuromodulators (NE/ACh). `runBrainSimulation(taskType)` is called before each revision to produce `snnValues` that are folded into the system prompt; `rewardBrain(value)` applies reward-modulated plasticity after a successful write-back. `rewardBrainWithConciseness(baseReward, result, { rawText, taskType, length })` is the ConciseRL-style dynamic variant: it scales the dopaminergic update by `scoreConciseness()` (lexical density minus expansion and overthinking penalties) so concise outputs reinforce more strongly. State is persisted to `chrome.storage.local`. If the simulation throws, `engine.js` logs a warning and falls back to a static prompt — preserve this fault tolerance when modifying.
- **Mnemonist memory** (`memory.js`, ported from `mnemonist_memory.py`): opt-in (`memoryEnabled`, default off, Settings → "Remember related prompts") because it sends earlier requests to the provider with the new one. After each successful revision `rememberRevision()` stores the request (≤ `MEMORY_RAW_CHARS`) and a prompt excerpt (≤ `MEMORY_PROMPT_CHARS`), masked by `redact.js`, at the next step of a loci route (`mnemonistMemoryV1`, ≤ `MEMORY_MAX_NODES`; a repeated request supersedes the old one). `prepareRevision()` calls `recallForRevision()`: up to `MEMORY_RECALL_TOP_K` active memories whose folded content words cover ≥ `MEMORY_MIN_SCORE` of the request (the identical request is skipped) go to `buildUserMessage({ memoryContext })` as an escaped `<past_work>` block with data-only rules — the RAW TEXT always wins. The synesthetic signature is a hash-derived label only; do not let it affect ranking, it carries no meaning. Recall and store fail open (empty / null), so memory can never block a revision. The `memory` flag is part of the semantic-cache fingerprint (appended only when on, so older keys stay valid). Active forgetting: the `MEMORY_FORGET` message (sent when a history entry is deleted or history is cleared) tombstones and sweeps matching memories; Settings can clear all. The `done` message carries `memoryUsed`, shown in the studio as `· memory n`. The pure functions take and return state objects without mutating them.
- **Efficiency layer** (`efficiency.js`): outermost semantic cache (`semanticCacheLookup`/`semanticCacheStore`, storage key `semanticCacheV1`, LRU-capped with TTL, exact plus Jaccard-similarity match gated on the full config fingerprint) short-circuits repeated queries before SNN/HDA/API in `prepareRevision()`; Psi-safe compression (`compressSystemPrompt`, Psi = protected-line survival, `PROTECTED_PATTERNS` covers fidelity rules, language mandate, output format, HDA markers and the concise-reasoning guard) prunes only unprotected filler and aborts if Psi < 1; block-level KV prefix caching (`toCacheableSystemBlocks` attaches Anthropic `cache_control` breakpoints to the stable instruction prefix, `prefixCacheKey` fingerprints it) is applied in `api.js` for long Anthropic system prompts; pyramidal retention (`pyramidRetentionForBlock`/`applyPyramidRetention`) keeps early blocks at full resolution and compresses deeper blocks progressively. `prompt.js` adds the `CONCISE_REASONING_GUARD` (task-budgeted `<thought>` blocks via `reasoningBudgetFor()`) to block overthinking at the source.
- **`engine.js` message router** handles two `chrome.runtime` message types: `REVISE_PROMPT` (one-shot revision) and `REWARD_BRAIN` (post-hoc reward signal; the studio sends +1 on copy, -1 on redo) — both async, return `true` from the listener so `sendResponse` works. The studio's primary path is a port (`chrome.runtime.connect({ name: "revise" })` + `REVISE_PROMPT_STREAM` message) that streams `{type:"delta"}` chunks, optional `{type:"hda"}` / `{type:"checking"}` progress, then `{type:"done"|"error"}`. Both paths share `prepareRevision()` for strategy resolution, SNN tick and prompt assembly. A `skipCache: true` field on the message (the studio's Redo) bypasses the semantic-cache lookup so the user gets a fresh write; the new result still replaces the cached entry.

## Conventions worth knowing

- Code comments and UI strings are in English — keep new user-facing strings and comments in English to match.
- All persistent state lives in `chrome.storage.local` (browser `localStorage` via the shim, keys prefixed `metaprompt:`). Notable keys: `provider`, `anthropicKey`/`anthropicModel`, `openrouterKey`/`openrouterModel`, `openrouterWorkingModels`, `crossProviderFallback`, `typesafeKey`/`typesafeEnabled`/`typesafeMinConfidence`, `language`, `length`, `mode`, `agentTarget`, `placeholderValues`, `consensusCheck`, `hdaMode` (legacy `hdaEnabled`), `history` (obfuscated, 5 items, one per source text), `tipsSeen` (first-run tips dialog), `lastError`, `semanticCacheV1`, `memoryEnabled`/`mnemonistMemoryV1`, plus the SNN state keys written by `brain_helper.js`.
- All JS is ES modules loaded with `<script type="module">` except `web/shim.js` (classic script). Dynamic `import()` is used for the `brain_helper.js` reward path to avoid loading it on every page load.
- The verification scripts are standalone — not wired into the app. `verify_prompt.js` covers the prompt layer (315 structural checks, 23 of them Turkish task detection, 71 for the HDA layer and its phase agents, 46 for the Feynman rules, 48 for the Caveman rules, 27 for the Agent CLI mode); `verify_brain.js` covers the SNN; `verify_runtime.mjs` covers provider key isolation, the failover contract, streaming failure handling and TypeSafe fail-open against offline mocks; `verify_efficiency.js` covers the semantic cache, Psi-safe compression, ConciseRL-style reward and block/pyramid KV; `verify_memory.mjs` covers the Mnemonist memory (shorthand parity with the Python original, loci route, recall and diacritic folding, active forgetting, opt-in and fail-open storage, the escaped `<past_work>` block and the cache fingerprint); `verify_placeholders.mjs` covers the placeholder filler (extraction false positives, Turkish names, one-pass substitution with `$` in values, type classification, raw-text candidates, prefill-vs-suggest, and what is never remembered); `verify_web.mjs` covers the web bridge (storage forms, non-finite numbers, ports, `sendMessage`), the static server's path guard, the page/script id contract and the CSP allowlist. `node verify_prompt.js --show "<raw text>"` dumps the system prompt + user message a given input would produce.
- When you change behaviour that a script asserts, update the assertion to the new contract rather than loosening it until it passes.
